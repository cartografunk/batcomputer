# Decisiones, supuestos y límites

- No se adjuntó informe de investigación. Se usó FastAPI, LangGraph, SQLAlchemy y PostgreSQL según la base solicitada. SQLite permite desarrollo local sin contratar servicios.
- La autenticación inicial usa tokens opacos configurados en servidor y su hash como propietario. Es sencilla y reemplazable por identidad de Supabase cuando el producto defina cuentas. El token de acceso que escribe el usuario permanece en memoria del navegador, no es la clave del modelo.
- Una salida `question` de Planner evita reimplementación y termina en `answered`. Una ambigüedad bloqueante termina en `needs_clarification`; la pregunta pendiente se guarda en la conversación y se entrega al Planner en el siguiente turno. Para tickets, Coder entrega una instantánea completa de archivos aprobados previos. Las propuestas rechazadas y el feedback no reemplazan ese contexto, pero quedan auditables.
- El Reviewer examina el código y recibe el estado de validación aislada como evidencia. `MAX_CODER_ATTEMPTS=3` limita gasto y ciclos improductivos: primer intento + dos correcciones. La última revisión rechazada produce `exhausted`; no se presenta como aprobado. Los reintentos de API son independientes.
- Los trabajos se almacenan antes de responder `202`. PostgreSQL usa un bloqueo transaccional global breve para reclamar y aplicar el límite de concurrencia; también impide cambios simultáneos dentro de una conversación. Tras `JOB_STALE_SECONDS`, el worker recupera un trabajo hasta `MAX_JOB_RECOVERIES` veces. Un lease impide que un worker anterior persista un resultado tras nueva reclamación. Aun así, una llamada al modelo o al sandbox puede duplicarse antes del cierre: el sistema ofrece entrega al menos una vez, no ejecución exactamente una vez. Tras una caída de base, el estado puede no actualizarse hasta restablecer conexión. Ajuste `JOB_STALE_SECONDS` por encima del máximo de llamada y reintentos.
- E2B se eligió porque su SDK Python permite sandbox efímero, red desactivada, archivos, comandos con timeout y cierre explícito. `E2B_API_KEY` autentica la llamada al control plane; no se envían `MODEL_API_KEY`, `DATABASE_URL` ni variables de aplicación al sandbox (`envs={}`). Sin clave, el resultado es `not_executed`. Un fallo de compilación/pruebas es `failed`; un fallo del servicio E2B es `error` y no implica automáticamente código incorrecto. [Referencia SDK E2B](https://e2b.dev/docs/sdk-reference/python-sdk/v2.5.0/sandbox_sync).
- La interfaz es provisional y sustituible; el diseño de identidad visual está pendiente. El build estático se sirve desde FastAPI. La vista previa usa iframe de origen opaco y CSP restrictiva; recursos externos y llamadas de red se bloquean, aunque no equivale a un análisis de seguridad del HTML/JS. Flappy Bird funciona en `/flappy` como juego independiente; falta confirmar cómo integrarlo con el chat.
- Las trazas guardan solicitudes y respuestas relevantes, duración, revisión y errores públicos. Pueden contener datos del ticket o código; establezca retención, cifrado y controles operativos antes de uso sensible. No se solicita ni guarda razonamiento privado.
- El módulo vivirá separado de la web actual de Cartografunk, enlazado desde ella cuando se apruebe. El subdominio propuesto no existe todavía. La alternativa `/agentes` requiere revisar capacidades de proxy del hosting actual antes de implementarse. No se tocó el sitio ni DNS.
- Con más tiempo: identidad con sesiones y revocación, límites de uso atómicos distribuidos, métricas, pruebas con PostgreSQL y E2B reales, lease renovable durante llamadas largas, y aislamiento de la vista previa en un origen distinto.
