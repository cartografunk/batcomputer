# Decisiones, supuestos y límites

- No se adjuntó informe de investigación. Se usó FastAPI, LangGraph, SQLAlchemy y PostgreSQL según la base solicitada. SQLite permite desarrollo local sin contratar servicios.
- La autenticación inicial usa tokens opacos configurados en servidor y su hash como propietario. Es sencilla y reemplazable por identidad de Supabase cuando el producto defina cuentas. El token de acceso que escribe el usuario permanece en memoria del navegador, no es la clave del modelo.
- Una salida `question` de Planner evita reimplementación y termina en `answered`. Para tickets, Coder entrega una instantánea completa de archivos. Así puede partir de archivos aprobados y el historial de versiones sigue auditable.
- El Reviewer examina el código estáticamente. `MAX_CODER_ATTEMPTS=3` limita gasto y ciclos improductivos: primer intento + dos correcciones. La última revisión rechazada produce `exhausted`; no se presenta como aprobado. Los reintentos de API son independientes.
- Los trabajos se almacenan antes de responder `202`. PostgreSQL usa bloqueo transaccional por conversación al reclamar; el worker recupera trabajos cuya señal quedó obsoleta. Un identificador de posesión impide que un worker anterior persista su resultado tras una nueva reclamación. Tras una caída de base, el estado puede no actualizarse hasta restablecer conexión. Ajuste `JOB_STALE_SECONDS` por encima del máximo de llamada y reintentos del modelo para evitar reclamación prematura.
- No se ejecuta código generado ni se instala un sandbox. Añadir ejecución requiere un servicio aislado sin credenciales, límites de recursos y una política explícita. Docker por sí solo no cumple esa función.
- La interfaz es provisional y sustituible. Flappy Bird funciona en `/flappy` como página independiente; falta confirmar cómo integrarlo con el chat.
- Las trazas guardan solicitudes y respuestas relevantes, duración, revisión y errores públicos. Pueden contener datos del ticket o código; establezca retención, cifrado y controles operativos antes de uso sensible. No se solicita ni guarda razonamiento privado.
- Con más tiempo: identidad con sesiones y revocación, límites atómicos distribuidos, migraciones versionadas, métricas, pruebas con PostgreSQL real, detección de trabajos vivos mediante lease renovable y sandbox separado para pruebas de código.
