# Decisiones, supuestos y límites

- El rediseño solicitado añadió Router, criterios de aceptación estrictos, Tester determinista, Documenter, checkpoints SQLite y SSE. SQLite mantiene sesiones locales; por la decisión anterior de usar el proyecto Supabase compartido, las sesiones de producción siguen en PostgreSQL y los checkpoints de LangGraph se guardan en un volumen SQLite separado. Una sola réplica de Railway debe acceder al volumen; no se escala horizontalmente hasta migrar el checkpointer a PostgreSQL.
- El acceso web usa una cookie anónima firmada por el servidor, `HttpOnly`, `SameSite=Lax` y `Secure` en producción. El usuario no introduce token y la clave del modelo nunca llega al navegador. `AUTH_TOKENS` permanece en el servidor como secreto de firma y para compatibilidad con clientes Bearer; al rotarlo se invalidan las cookies. Las sesiones anónimas se aíslan por propietario, pero no constituyen identidad de usuario y pueden reemplazarse por Supabase Auth cuando el producto defina cuentas. Además del límite por sesión, un límite global por hora acota el gasto público.
- Por decisión del propietario, Batcomputer comparte el proyecto Supabase `cartografunk` y tiene un esquema PostgreSQL propio llamado `batcomputer`. Las migraciones califican todos los objetos con ese esquema; la conexión de SQLAlchemy fija su `search_path`. El esquema no se expone a la Data API y sus tablas tienen RLS sin políticas públicas. El rol `batcomputer_app` recibe permisos solo sobre ese esquema y se usa en Railway mediante Session pooler; no se usa la credencial administradora `postgres` en la aplicación.
- Router diferencia `NEW_TICKET`, `MODIFICATION` y `QUESTION`; Question responde sin entrar al Coder. Una ambigüedad bloqueante del Planner termina en `needs_clarification`; la pregunta pendiente se guarda en la conversación y se entrega al Planner en el siguiente turno. Para tickets, Coder recibe solo los criterios, archivos previos, fuentes y feedback, y entrega una instantánea completa. Las propuestas rechazadas y el feedback quedan auditables.
- El Tester analiza sintaxis Python/JSON localmente sin ejecutar código; E2B continúa para ejecución aislada Python cuando tiene clave. Un resultado `failed` fuerza rechazo del Reviewer con stderr exacto. `MAX_CODER_ATTEMPTS=3` limita gasto y ciclos improductivos: primer intento + dos correcciones. La última revisión rechazada produce `exhausted`; no se presenta como aprobado. Documenter registra un resumen y un README incluso en el agotamiento. Los reintentos de API con Tenacity son independientes.
- Los trabajos se almacenan antes de responder `202`. PostgreSQL usa un bloqueo transaccional global breve para reclamar y aplicar el límite de concurrencia; también impide cambios simultáneos dentro de una conversación. Tras `JOB_STALE_SECONDS`, el worker recupera un trabajo hasta `MAX_JOB_RECOVERIES` veces. Un lease impide que un worker anterior persista un resultado tras nueva reclamación. Aun así, una llamada al modelo o al sandbox puede duplicarse antes del cierre: el sistema ofrece entrega al menos una vez, no ejecución exactamente una vez. Tras una caída de base, el estado puede no actualizarse hasta restablecer conexión. Ajuste `JOB_STALE_SECONDS` por encima del máximo de llamada y reintentos.
- E2B se eligió porque su SDK Python permite sandbox efímero, red desactivada, archivos, comandos con timeout y cierre explícito. `E2B_API_KEY` autentica la llamada al control plane; no se envían `MODEL_API_KEY`, `DATABASE_URL` ni variables de aplicación al sandbox (`envs={}`). Sin clave, el resultado es `not_executed`. Un fallo de compilación/pruebas es `failed`; un fallo del servicio E2B es `error` y no implica automáticamente código incorrecto. [Referencia SDK E2B](https://e2b.dev/docs/sdk-reference/python-sdk/v2.5.0/sandbox_sync).
- La interfaz actual adapta la identidad visual de Cartografunk y puede sustituirse cuando llegue el diseño definitivo. El build estático se sirve desde FastAPI. La vista previa usa iframe de origen opaco y CSP restrictiva; recursos externos y llamadas de red se bloquean, aunque no equivale a un análisis de seguridad del HTML/JS. Flappy Bird funciona en `/flappy` como implementación independiente del entregable 5 del enunciado; no se presenta como código generado por los agentes. La generación de juegos por el chat se evalúa aparte con `S7-flappy`.
- Las trazas guardan solicitudes y respuestas relevantes, duración, revisión y errores públicos. Pueden contener datos del ticket o código; establezca retención, cifrado y controles operativos antes de uso sensible. No se solicita ni guarda razonamiento privado.
- `cartografunk/batcomputer` es el repositorio entregable de la aplicación completa y se instala sin `cartografunk/cartografunk_web`. Este último sigue alimentando `www.cartografunk.com`; Batcomputer se sirve desde Railway en `batcomputer.cartografunk.com` con DNS gestionado en Cloudflare. La aplicación incluye un enlace de regreso. Consulte [DOMAIN.md](DOMAIN.md).
- Con más tiempo: identidad con sesiones y revocación, límites de uso atómicos distribuidos, métricas, pruebas con PostgreSQL y E2B reales, lease renovable durante llamadas largas, y aislamiento de la vista previa en un origen distinto.
